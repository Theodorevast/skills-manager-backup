# 素材中台（vmc）

用户所在公司有一个素材中台，官方命令行 `vmc` 是专门给 AI 用的：输出 JSON，下单前先出计划。Claude、Codex、Grok 都能用，被派出去的写任务里也能用（已实测）。

找不到 `vmc` 命令时用完整路径：`"$HOME/.local/bin/vmc"`。

## 最重要：不做危险操作

这是公司账号，素材中心是全公司共用的。只做：查看、搜索、查配额、用户确认过的生成、下载到本地项目。**不做**：删除、覆盖、移动、重命名任何素材或文件夹；往公司素材库或共享文件夹上传或转存（`--folder`），除非用户这一次指定了文件夹；分享、发布、提交审核、评论、发通知；修改共享内容（Skill 助手、可灵主体库等）；改设置、权限，创建或吊销令牌；批量下载公司素材。拿不准的按钮不点，先问用户。点错了立刻停下告诉用户，不要自己补救。

## 什么时候用它

| 要做的 | 用什么 |
|---|---|
| 图片：概念图、参考图、贴图底色、图标、海报，含透明底、图生图、批量 | **vmc**（优先） |
| 视频：文生视频、图生视频、首尾帧、有声视频 | **vmc** |
| 3D 模型 | 不用 vmc，走 `game-assets` skill 里的 Tripo 流程 |
| 中台网页上的模型素材生产、AI 语音、素材清洗、内容反推、Skill 助手、模板生视频、可灵主体库、素材中心搜索 | 命令行不支持，用户的账号权限也开不了。按下面"网页上才有的功能"处理 |
| vmc 报配额用完或服务不可用 | 告诉用户；用户同意后才换用 `game-assets` 里的生图工具 |

## 第一步：先问用户，不要自己选模型

**每一次生图、生视频之前，都要先问用户，等他回答再往下走。** 不要自己决定走哪条路、用哪个模型、版本、尺寸、数量，哪怕你很确定哪个最合适。

0. **先问走哪条路**，有些特殊场景用户要用特定的模型：
   - 公司素材中台（`vmc`）：GPT Image、NanoBanana、Seedream、可灵、Seedance、Veo、MiniMax
   - Codex 自带的生图
   - Grok 自带的生图、改图、生视频（Grok Imagine）
   - 其他（用户指定）

   用户选了某一家的自带工具，就由那一家来做：你自己就是那一家，直接在当前对话里做；不是的话，用 `team-sync` 把活派给它，`team post` 要加 `--gen`，任务单里写明"用户已确认用你自带的工具"以及确认过的提示词、数量、尺寸。不加 `--gen` 的派出任务里，自带生成工具是关着的。
1. 选了中台时，运行 `vmc models image` 或 `vmc models video`，拿到**此刻**可用的模型（服务端会变，不要凭记忆）。
2. 把选项用大白话列给用户，每个模型一句话说它擅长什么，再写出你推荐哪个、为什么。然后问清下面这些：

   | 生图要问 | 生视频要问 |
   |---|---|
   | 用哪个模型（和版本） | 用哪个模型 |
   | 尺寸或比例 | 时长、比例、分辨率 |
   | 出几张 | 要不要声音 |
   | 要不要透明底 | 用不用参考图或首帧图 |
   | 质量档位（只有 GPT 有） | 出几条 |

3. 把你准备用的提示词也给用户看一眼，用户可以改。
4. **用户的回答里没说的项，不要自己填**，再问一次，或者明确说"这项我用默认值 X，可以吗"。
5. 只有用户在这次请求里已经点名了某项（例如"用 seedream 出 4 张 2K 的"），那一项才不用问。
6. 批量任务（多张、多条、多个提示词）同样要问，而且要把总数和总配额说清楚。
7. 用户说"以后这个项目都用某某模型"时，把它记进项目 `AGENTS.md` 的一行 `素材中台默认：<生图模型和参数>；<生视频模型和参数>`。之后可以直接用这个默认值，但仍然要在计划里写出来让用户看到。用户没这样说过，就每次都问。

问完、用户答完，才进入下面的铁律。

## 铁律：先给用户看计划，确认后才提交

这一条和 vmc 自己的规则一致，**每一次真实生成都要遵守**：

1. 先运行**不带 `--yes`** 的命令。vmc 会输出计划并以退出码 5 结束（`CONFIRMATION_REQUIRED`），计划里有模型、数量、配额前后、费用预估。
2. 把计划原样告诉用户：用了哪个模型、出几张或几条、配额会从多少变成多少、费用多少。
3. 用户明确同意后，**同一条命令**加 `--yes` 再运行。参数一个都不能改，改了就是新的计划，要重新确认。
4. 只想看看要花多少：用 `--dry-run`。
5. 不要为了"测试能不能用"去真的生成。测连通用 `vmc whoami`、`vmc quota`、`vmc models`，这三条不花钱。

### 派给别家时

被派出去的 AI 在无界面会话里，没法问用户。所以：

- **发起方**先在自己的对话里问清模型和参数（第一步）、拿到计划、得到用户确认，再派活。任务单里写明"用户已确认以下计划"，并给出**完整的命令**（带 `--yes`）。
- 接活的一方只运行任务单里那条命令，原样运行，不改参数，不加量。任务单里没写"用户已确认"的，只能用 `--dry-run`，把计划写进结果交回。
- 写任务的 `--paths` 要包含输出目录（见下）。生成任务优先派给 Grok（额度宽裕）；Claude、Codex 也可以。

## 结果放哪

放在当前项目里，和其他素材的规矩一致：

```
<项目>/assets/generated/vmc/<任务ID>/
```

- 用 `--out <项目>/assets/generated/vmc` 下载，vmc 会建 `<任务ID>` 子目录。
- 把 vmc 输出的完整 JSON 存成同目录下的 `vmc-result.json`，里面有提示词、模型、参数和原始地址，以后要复现或追溯都靠它。
- 原图是**母版**，不要覆盖、不要就地压缩。网页要压缩、引擎要导入，都写到项目的派生目录，并记下来源。
- 需要放进公司素材库时用 `--folder <文件夹ID>`；文件夹 ID 问用户，不要猜。

## 常用命令

```bash
vmc whoami                     # 当前登录用户
vmc quota                      # 今日配额（图片按张，视频按条）和在途任务
vmc models image               # 图片模型、版本、合法尺寸（服务端下发，每次现查）
vmc models video               # 视频模型、时长、分辨率、比例、是否有声

# 生图：先不带 --yes 拿计划，用户确认后加 --yes
vmc image gen --prompt "…" --model gpt --size 1024x1024 --count 1 --out "<项目>/assets/generated/vmc"
vmc image gen --prompt "…" --model gpt --background transparent --out "<项目>/assets/generated/vmc"     # 透明底
vmc image gen --prompt "换成雪地背景" --ref ./a.png --model nanobanana --size 16:9 --out "<项目>/assets/generated/vmc"
vmc image batch --file prompts.jsonl --model gpt --out "<项目>/assets/generated/vmc"                    # 每行一个 JSON 或纯文本提示词

# 生视频
vmc video gen --model kling-v3 --prompt "…" --duration 5 --ratio 16:9 --out "<项目>/assets/generated/vmc"
vmc video gen --model seedance-2.5 --ref ./frame.png --prompt "…" --audio --out "<项目>/assets/generated/vmc"

# 任务
vmc task list --limit 5
vmc task get img_123
vmc task wait img_123 vid_45 --out "<项目>/assets/generated/vmc"
vmc task cancel vid_45
```

模型、尺寸、时长、是否支持有声，**以 `vmc models` 的实时结果为准**，不要凭这份说明或记忆判断。

## 出错时

| 退出码 | 含义 | 怎么做 |
|---|---|---|
| 3 | 未登录或令牌过期（令牌 30 天有效） | 告诉用户在 Claude Code 输入框里运行 `! vmc login`，或在终端运行 `vmc login`。**不要替用户登录** |
| 4 | 今日配额用完或在途任务太多 | 不要重试，告诉用户 |
| 5 | 需要确认 | 正常流程，见铁律 |
| 6 | 任务失败 | 把错误原样告诉用户，不要自动换参数重试 |
| 7 | 网络或服务端错误 | 带 `--yes` 的提交可以原样重跑一次：服务端 10 分钟内按参数去重，输出 `replayed: true` 表示复用了已创建的任务 |

## 不要做的

- 不要读、打印或复制 `~/.config/vmc/credentials.json`，令牌不能出现在任务单、提示词、日志或项目文件里。
- 不要在项目里运行 `vmc init`。这份共享 skill 已经覆盖它的内容，再写一份会让项目里出现两套说明。
- 不要用浏览器自动操作中台网页。
- 汇报时分开说：已提交、已生成、已下载到哪里、是否检查过。只引用这一次任务的结果。

## 网页上才有的功能

模型素材生产（3D）、AI 语音、素材清洗、内容反推、Skill 助手、模板生视频、可灵主体库、素材中心搜索下载，只能在网页 https://vast-material.tripo3d.com 上做。分两种情况：

### 用户在（默认）

把用户需要的东西全部准备好，让用户手动操作：

1. 打开哪个页面（左侧菜单的名字）。
2. 每个选项选什么、每个输入框填什么，按页面上从上到下的顺序写。提示词、文案写成可以直接复制的完整文本。
3. 要上传的文件：写出完整路径，必要时先把文件准备好放进项目。
4. 结果下载后放到项目哪个目录、叫什么名字。用户放好后，你接着做后面的步骤。

不确定页面长什么样时，先问用户要一张截图，不要凭想象写按钮名字。

### 用户不在，但要 AI 继续干

只有用户明确说了"我不在，你自己去网页上做"这类话，才用浏览器工具 `vast-web` 自己操作网页。

- **用户离开前要把会花钱的事说定**：做什么、用哪个功能和模型、做几个、最多花多少。没说定的，不要在网页上提交任何会消耗配额或积分的操作，把准备好的内容留着等用户回来。
- 浏览器用的是一个只给中台用的专用身份。只访问中台网页（含飞书登录页），不要用它去别的网站。
- 第一次用或登录过期时，网页会跳到飞书登录。你没法替用户登录：停下来，告诉用户在终端运行 `vast-web-login`，在弄开的窗口里用飞书登录，登录完按 ⌘Q 关掉那个窗口。
- 同一时间只能有一个浏览器使用这个身份。开工前用 `team claim` 登记占用 `browser:vast-web`；做完调用 `browser_close` 关掉浏览器，再 `team release`。被告知"已被占用"时等对方用完。
- 每一步操作前先看页面（快照或截图），确认按钮和选项是对的再点。提交前截一张图存进项目 `assets/generated/vast-web/`，结果下载到同一目录，文件名带上日期和功能名。
- 被任务板派出去的无界面任务里不要用浏览器：沙箱会拦住浏览器写自己的配置。网页操作由发起方在自己的对话里做。
- 用户回来后，汇报做了哪些操作、提交了什么、花了多少配额、结果放在哪，附上提交前的截图。
