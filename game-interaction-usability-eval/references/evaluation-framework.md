# 游戏交互易用性评估框架

## 角色视角

从三类视角综合判断：

- 玩家视角：分别代入新手、中度、硬核玩家，关注操作习惯、心理预期、理解路径、情绪反馈和疲劳来源。
- 游戏交互设计师视角：结合 HCI、游戏 UX、商业化逻辑、信息架构、行为设计和反馈机制，解释问题原因与设计取舍。
- 技术与项目协作视角：预判实现难度、开发成本、动效与性能影响、多端适配风险，并判断是否适合当前版本推进。

## 核心原则

1. 先理解设计目标，再评估问题。若问题来自产品目标与易用性的冲突，说明牺牲了哪些体验、是否存在折中方案、当前取舍是否值得保留。
2. 先描述观察结果，再判断问题。先写“我看到了什么”，再写“这里可能导致什么体验问题”。
3. 区分确认问题与无法确认。静态素材无法确认动效、音效、触觉、Hover、自动折叠、状态切换、二级交互层等。
4. 尊重合理取舍。用弹性表达，例如“如果该设计是为了强化商业化曝光，则具备合理性；否则建议降低视觉干扰”。
5. 玩家真实感受优先，理论作为佐证。避免连续堆叠理论名词。
6. 避免抽象建议。建议必须包含调整对象、调整方式、调整原因、预期收益。
7. 静态素材结论要降置信度，并主动建议补充多状态截图、流程说明或录屏。
8. 结合行业成熟方案、同品类头部竞品、平台习惯和玩家长期路径判断偏离是否有收益。

## 理论参考

- HCI：Nielsen 十大可用性启发原则、Norman 设计心理学、Fitts 定律、Hick 定律、Miller 7±2、Don't Make Me Think。
- 游戏 UX：MDA 框架、心流理论、Bartle 玩家动机模型、反馈循环、操作负荷与认知负荷。

理论名称只做辅助说明，不要替代玩家体验描述。

## 评分标准

| 分值 | 含义 |
|---|---|
| 5 | 行业优秀水平 |
| 4 | 体验成熟稳定 |
| 3 | 可用但存在摩擦 |
| 2 | 容易造成困惑 |
| 1 | 严重影响核心体验 |

## 十大评估维度

| 维度 | 关注点 |
|---|---|
| 可学习性 | 新玩家能否快速理解功能作用、操作方式、系统逻辑 |
| 可操作性 | 按钮尺寸、交互区域、点击路径是否符合平台操作习惯 |
| 信息架构 | 信息层级、导航结构、内容分组是否清晰 |
| 视觉可用性 | 信息层次、对比度、可读性、图标辨识度 |
| 反馈系统 | 操作反馈是否即时、明确、符合预期，包括动效、音效、数值反馈、状态变化 |
| 容错与恢复 | 是否容易误操作，是否有撤销机制或风险提示 |
| 效率与流畅性 | 高频路径是否足够短，是否支持快捷、批量、自动化操作 |
| 情境适应性 | 是否随战斗状态、新手阶段、成长阶段调整信息密度与交互形式 |
| 无障碍支持 | 色弱适配、字号、对比度、长时间阅读舒适性 |
| 情感化设计 | 是否符合世界观、具备沉浸感、强化情绪反馈、形成记忆点 |

## 玩家阶段差异

| 玩家类型 | 关注重点 |
|---|---|
| 新手玩家 | 学习成本、首次理解、引导是否自然 |
| 中度玩家 | 操作效率、流程顺畅度、常用路径是否稳定 |
| 硬核玩家 | 高频操作效率、批量路径、可跳过与快捷能力 |

分析当前设计更偏向服务谁，哪类玩家损耗最大，是否存在阶段体验断层。

## 严重性与置信度

| 等级 | 定义 | 处理优先级 |
|---|---|---|
| P0 致命 | 阻断核心流程 | 必须立即修复 |
| P1 严重 | 严重影响体验 | 当前版本修复 |
| P2 一般 | 存在明显摩擦 | 近期迭代优化 |
| P3 建议 | 体验增强项 | 长期优化 |

| 置信度 | 含义 |
|---|---|
| 确认 | 可以明确确认问题存在 |
| 疑似 | 基于静态素材或有限信息推测 |
| 待确认 | 当前素材无法判断，需要补充状态、录屏或说明 |

## 简报模式模板

### 1. 输入信息确认

复述游戏类型、平台、范围、素材类型、已知说明、无法确认项。

### 2. 界面现状概述

客观描述布局结构、主要功能区、视觉重心、交互入口。

### 3. 核心问题 Top 列表

| 问题 | 严重等级 | 置信度 | 改进建议 |
|---|---|---|---|

每条建议必须具体到对象与调整方式。

### 4. 总结建议

概括当前核心问题、优先优化方向、最值得先处理的体验问题。

## 完整模式模板

### 1. 输入信息确认

复述游戏类型、平台、评估范围、素材类型、已补充说明、缺失信息。

### 2. 界面现状客观描述

描述布局结构、功能区域、视觉风格、信息层级、交互路径。避免提前下结论。

### 3. 推测设计目标与产品策略

说明当前界面可能服务的目标，例如活动曝光、商业化转化、抽卡仪式感、新手留存、战斗沉浸、高频效率。

### 4. 十大维度评分总览

| 维度 | 评分 | 一句话评价 |
|---|---|---|

### 5. 玩家阶段差异分析

| 玩家阶段 | 主要体验问题 | 当前影响 |
|---|---|---|

补充说明当前更偏向服务哪类玩家，以及哪类玩家体验损耗最大。

### 6. 逐维度详细诊断

每个维度包含：

- 现状描述
- 问题发现
- 严重等级
- 置信度
- 关联理论
- 改进建议
- 实现难度：低 / 中 / 高
- 性能或多端适配风险
- 是否适合当前版本推进

### 7. 行业竞品与成熟方案对比

| 当前设计 | 行业常见方案 | 差异分析 | 是否建议调整 |
|---|---|---|---|

补充竞品为什么这样设计、解决了什么问题、玩家是否已经形成习惯、当前方案是否值得偏离行业共识。

### 8. 改进建议优先级矩阵

| 优先级 | 问题概述 | 严重等级 | 实现难度 | 建议措施 |
|---|---|---|---|---|

### 9. 亮点与值得保留的设计

至少列出 2 项。说明为什么有效、为什么值得保留、后续迭代中避免误改什么。

### 10. 总结与下一步建议

包含整体易用性水平、Top 3 优先问题、下一阶段建议、建议补充素材。

### 11. 界面策略倾向总结

| 维度 | 当前倾向 |
|---|---|
| 新手友好性 | 高 / 中 / 低 |
| 商业化曝光 | 高 / 中 / 低 |
| 沉浸感优先 | 高 / 中 / 低 |
| 操作效率优先 | 高 / 中 / 低 |
| 信息密度 | 高 / 中 / 低 |

分析当前设计是否符合产品目标、是否存在策略冲突、是否需要重新平衡方向。

## 建议措辞

优先写：

- “玩家第一次进入时，可能很难第一时间意识到这里可以横向滑动。”
- “如果该入口承担活动曝光目标，当前突出程度有合理性；但建议降低与主操作按钮的视觉竞争。”
- “当前无法从静态截图判断是否存在点击反馈。若未设计，建议加入 100-150ms 的按压态与轻量音效反馈。”

避免写：

- “这里设计错误。”
- “缺少反馈系统。”除非可以明确确认。
- “建议优化层级。”
- “违反 Nielsen 原则。”不要让理论替代问题描述。
